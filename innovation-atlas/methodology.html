Data & method, honestly.

A map is only as trustworthy as its sources. Here is exactly where every coordinate and boundary comes from — and, just as important, what is still an estimate.

Coordinates

Verification uses Singapore's official OneMap search API, reconciled by scripts/geocode.mjs with a 2 km sanity gate that rejects wrong-entity matches (a hotel "at Raffles Place", a building 12 km from the right campus). The two tiers are deliberate — there is no "trust me" tier:

onemap a real coordinate confirmed against OneMap.
estimated hand-placed, because the site isn't resolvable in the OneMap gazetteer by name (informal or brand-new — e.g. BLOCK71, Punggol Digital District, Tengah). Flagged in its map popup, and listed here:

District boundaries

The shaded cluster outlines are real boundaries, not hand-drawn shapes: the URA Master Plan 2019 Subzone Boundary (No Sea) dataset, published on data.gov.sg. scripts/extract-boundaries.mjs takes each cluster's anchor institution and finds the URA subzone polygon that actually contains it (point-in-polygon), then bakes those real polygons into the page.

One honesty note: a subzone is not the same thing as the informal "district". Each outline is therefore labelled by its true URA name — and the data sometimes corrects a popular assumption (NTU and CleanTech Park sit in the Western Water Catchment planning area, not "Jurong"). Where the official map agrees with the cluster, it agrees strongly — there is literally a subzone named "Singapore General Hospital".

Sources

  • Coordinates — OneMap, Singapore Land Authority. Free search API, no key required for search.
  • District boundaries — URA Master Plan 2019 Subzone Boundary (No Sea), via data.gov.sg.
  • Base map — CARTO Positron tiles on OpenStreetMap data.
  • Site selection & the cluster narratives — my own curation and analysis. These are editorial judgement, not sourced fact, and are kept in a separate file (js/content.js) from the dataset for exactly that reason.

What this is not (yet)

Reproducible

Nothing here is a black box. The dataset is plain data.js (also mirrored as data.json); the two tooling scripts re-run from the command line:

node scripts/geocode.mjs — re-verify coordinates against OneMap
node scripts/extract-boundaries.mjs — re-pull boundaries from data.gov.sg
